# Pitch video

- Length: 3 minutes 49 seconds, 1920x1080, 30 fps.
- Public link: https://youtu.be/aVK8SuRTMSU
- Every claim comes from the live desk, the tests or the live e2e run.
- The demo part is a screen recording of the deployed desk, not a mock-up.
- The video was made at commit c23a055b3, so it says 39 tests and 40 of 40 live checks. The current numbers are 51 tests and 43 of 43 live checks; the 3 new live checks are an upstream refusal mapped to 400 with nothing spent, and the 429 after 20 failed calls.
- Two more points in the video are older than the desk: the narration says "more than 20 failed calls", while the desk answers 429 to the call after 20 failed calls; and step 6 shows a `cd-receipt-v3` payload, while the desk now signs `cd-receipt-v4`, whose hashes are over canonical JSON.

| 1:28 | Terminal: the burst result, then `jq` over `e2e-live-output.json`: 40 of 40, and the 400 schema gate with nothing spent | The budget check is one conditional update, so it holds under load. Arguments are checked against the tool's input schema before any charge. Bad arguments get 400, nothing is spent, and the upstream is never called. A key with more than 20 failed upstream calls in one hour gets 429, because failed calls are free. |
| 1:58 | Terminal: `verify-receipt.mjs` on a real receipt and on a forged copy, the MCP receipt proof; then `architecture.svg` at the refund row | Receipts are Ed25519 over canonical JSON, so anyone can check one offline with the public key. The verifier runs four checks: the signature, the hash of the answer, the hash of the arguments you sent, and the readable copy. Change one digit of the amount, and it prints valid false and exits with code 1. Over MCP, every tools/call result now carries the whole signed receipt, and the verifier proves the answer from that result alone. If the upstream is slow, the agent gets 504. If it fails, it gets 502. Both are refunded in the same batch that writes the receipt. |
| 2:34 | Operator console, the price list with added MCP tools (one with a sealed credential), the Create key form, the daily key from the live e2e run, the audit log | Operators get a console behind a bearer token. An operator can add a tool from any MCP server with one admin call, or with the Add a tool form. No deploy. The desk reads that server's tools list for the input schema. A credential header for that server is sealed with AES-256-GCM and never shown again. The live test adds DeepWiki's read wiki structure tool, clears it on a daily key, then disables it. Budgets can reset daily or monthly, inside the same atomic reservation. Each response shows the budget period and when it resets. This daily key from the live test is spent until midnight UTC. The audit log and the receipts are append-only in the database. A receipt is visible only inside its own organization. |
